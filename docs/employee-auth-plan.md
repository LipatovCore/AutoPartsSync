# Статус реализации employee-auth

Документ больше не является планом на старте проекта. Он нужен как фиксация того, что из задуманного уже сделано и что осталось незавершённым.

## Реализовано

- кастомная модель пользователя `employees.Employee` с логином по email;
- статусы доступа `created`, `active`, `deactivated`;
- создание сотрудника и выпуск приглашения;
- хранение hash токена вместо сырого токена;
- TTL приглашения 24 часа;
- перевыпуск приглашения с отзывом предыдущего;
- установка пароля по одноразовой ссылке;
- перевод сотрудника в `active` после успешной установки пароля;
- деактивация сотрудника;
- административный сброс доступа активного сотрудника;
- завершение серверных сессий при активации, деактивации и сбросе доступа;
- аудит ключевых событий доступа;
- rate limit для логина, установки пароля и перевыпуска приглашения;
- группы `admin` и `user` через Django Groups/Permissions;
- ограничение доступа к employee-management по permission `employees.manage_employee_access`;
- доступ к журналу аудита по permission `employees.view_employee_access_audit`.

## Не реализовано

- автоматическая отправка приглашений по email;
- self-service восстановление пароля сотрудником;
- отдельный интерфейс просмотра аудита вне Django admin;
- отдельная бизнес-модель ролей поверх стандартных Django groups;
- вынос employee-auth тестов в отдельный пакет `src/employees/tests/` вместо одного файла `tests.py`.

## Открытый технический долг

### Тесты

Факт по репозиторию:

- `employees/tests.py` уже содержит большой набор тестов на employee-auth;
- отдельные тесты для `analogs` и `counterparties` почти отсутствуют.

Следствие:

- employee-auth покрыт заметно лучше остальных разделов;
- общий риск регрессий в проекте всё равно остаётся из-за слабого покрытия соседних модулей.

### UI и поток выдачи приглашений

Приглашение сейчас:

- создаётся в системе;
- показывается администратору один раз в интерфейсе;
- передаётся сотруднику вручную вне системы.

Это не ошибка документации, а реальное поведение текущего кода.

## Итог

Основной security-flow employee-auth в проекте реализован. Текущий незавершённый слой работ связан не с базовой доступностью фичи, а с удобством сопровождения и более широким покрытием тестами соседних модулей.
