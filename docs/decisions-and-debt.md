# Решения и технический долг

## Как читать документ

Ниже перечислены решения и проблемные зоны, подтвержденные репозиторием. Это не roadmap и не список общих пожеланий.

## Зафиксированные решения

### Django monolith

Evidence:

- один проект `src/config/`;
- локальные apps `src/analogs/` и `src/counterparties/`;
- единый settings module.

Impact:

- низкий порог входа;
- быстрый локальный запуск;
- высокая связность внутри одного процесса.

### Server-rendered UI

Evidence:

- основной интерфейс построен на `src/templates/`;
- DRF и serializers отсутствуют;
- auth идет через `django.contrib.auth.urls`.

Impact:

- backend и UI меняются вместе;
- шаблоны являются частью основного приложения, а не вторичным слоем.

### Прямой вызов внешних API из `analogs`

Evidence:

- `requests.get(...)` находится в `src/analogs/views.py`.

Impact:

- интеграционный flow прозрачен;
- тестирование и наблюдаемость усложнены.

## Технический долг

### 1. Интеграционная логика сосредоточена в `src/analogs/views.py`

Evidence:

- функции `search_article`, `ms_assort`, `search_ms`, `search` находятся в одном модуле;
- тот же модуль содержит HTTP handler и преобразование данных для шаблона.

Impact:

- высок риск регрессии при правке поиска;
- интеграции трудно тестировать отдельно;
- код сложнее переиспользовать.

Suggested remediation:

- выделить отдельный модуль внутри `src/analogs/` для работы с внешними API;
- отделить orchestration HTTP-запроса от запросов к внешним системам;
- после декомпозиции добавить тесты.

### 2. Автотесты отсутствуют

Evidence:

- `src/analogs/tests.py` пустой;
- `src/counterparties/tests.py` пустой;
- `manage.py test` возвращает `Found 0 test(s)`.

Impact:

- любой рефакторинг опирается на ручную проверку;
- regressions будут выявляться поздно.

Suggested remediation:

- начать со smoke tests для:
  - login-required страниц;
  - CRUD клиентов;
  - CRUD автомобилей;
  - базового сценария поиска.

### 3. В интеграции остатков захардкожен `storeId`

Evidence:

- `src/analogs/views.py` содержит `storeId=17cfc07f-d1be-11e7-7a34-5acf00029692`.

Impact:

- поведение привязано к одному складу;
- перенос в другое окружение становится хрупким;
- значение трудно отследить и обновлять.

Suggested remediation:

- вынести `storeId` в env/config;
- документировать его назначение;
- добавить явное поведение при отсутствии значения.

### 4. Ошибки интеграций логируются через `print(...)`

Evidence:

- в `src/analogs/views.py` ошибки `requests` обрабатываются через `print(...)`.

Impact:

- нет нормальной наблюдаемости;
- диагностика проблем осложняется;
- ошибки трудно собирать централизованно.

Suggested remediation:

- перейти на стандартный logging;
- отделить developer logs от user-facing сообщений.

### 5. Внешние HTTP-запросы выполняются синхронно в request path

Evidence:

- `requests.get(...)` вызывается непосредственно из view-функций.

Impact:

- задержка внешнего API напрямую влияет на ответ пользователю;
- retry и buffering отсутствуют.

Suggested remediation:

- в краткосрочной перспективе улучшить обработку ошибок и таймаутов;
- в среднесрочной перспективе рассмотреть кэширование и выделение модуля интеграции;
- фоновые задачи рассматривать только как отдельное архитектурное решение.

### 6. `client_detail.html` выглядит как legacy artifact

Evidence:

- шаблон `src/templates/counterparties/client_detail.html` существует;
- `client_detail` в `src/counterparties/views.py` делает redirect в workspace.

Impact:

- новый разработчик может начать менять неиспользуемый шаблон;
- навигация по коду усложняется.

Suggested remediation:

- подтвердить, нужен ли шаблон;
- затем либо удалить его отдельной задачей, либо явно пометить как legacy в коде и документации.

### 7. Инфраструктурные предпосылки не до конца согласованы

Evidence:

- в `src/config/settings.py` база данных - SQLite;
- в `Dockerfile` устанавливается `libpq-dev`.

Impact:

- непонятно, ожидается ли PostgreSQL;
- новый разработчик получает смешанные сигналы о целевом окружении.

Suggested remediation:

- подтвердить, нужен ли `libpq-dev`;
- либо документировать причину, либо удалить лишнюю зависимость.

### 8. Локаль и time zone требуют подтверждения

Evidence:

- `LANGUAGE_CODE = 'en-us'`;
- `TIME_ZONE = 'UTC'`;
- интерфейс проекта русскоязычный.

Impact:

- возможен конфликт между ожиданиями бизнеса и фактической конфигурацией;
- выше риск путаницы в датах и локали.

Suggested remediation:

- подтвердить настройки у владельца проекта;
- после подтверждения закрепить решение в документации.

### 9. Большие inline CSS/JS блоки в шаблонах

Evidence:

- `src/templates/base.html`;
- `src/templates/counterparties/client_list.html`;
- `src/templates/registration/login.html`.

Impact:

- UI труднее сопровождать;
- растет вероятность побочных эффектов при правке шаблонов.

Suggested remediation:

- выносить повторно используемые куски постепенно;
- не делать массовый frontend-refactor без отдельной задачи.

### 10. Отображение русскоязычных файлов в терминале не всегда надежно

Evidence:

- при чтении документов через PowerShell часть русскоязычного текста отображается как mojibake;
- в проекте много русскоязычных строк в шаблонах, моделях, формах и документации.

Impact:

- можно принять проблему консоли за проблему файла;
- возрастает риск случайно перезаписать корректный UTF-8 текст.

Suggested remediation:

- считать источником истины сами файлы, а не отображение терминала;
- не смешивать содержательные правки с массовым перекодированием;
- любые изменения кодировки делать отдельной задачей.

## Хрупкие области

- `src/analogs/views.py`
- `src/counterparties/views.py`
- `src/templates/counterparties/client_list.html`
- `src/templates/base.html`

Любые изменения здесь требуют ручной проверки затронутого пользовательского сценария.

## Кандидаты на будущий рефакторинг

- декомпозиция `src/analogs/views.py`;
- минимальное тестовое покрытие критических сценариев;
- решение по `client_detail.html`;
- нормализация конфигурации склада;
- решение по ожидаемой кодировке файлов.
